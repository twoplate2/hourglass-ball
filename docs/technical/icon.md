# 沙漏 App 启动图标制作经验教训（ICON.md）

> 记录 `apk/icon.png`（1024×1024）与 `apk/presplash.png`（1080×1920）从**锥形改球形**的
> 迭代过程与踩坑。图标与 `main.py` 的球形沙漏保持一致，但外观上它是一次**审美 + 物理逻辑**的
> 双重对齐，本轮踩了很多坑。事后重看，很多弯路本可避免。

---

## 一、最重要的判断（一句话）

**用户认可是"原版锥形的那套质感"（上下木盖 + 浅蓝玻璃 + 金沙 + 居中对称），只需要把中间的容器从"锥形"换成"球形"；不要换风格、不要过度加戏。**

第一版我直接推倒重做了个纯扁平 / 或加渐变浮雕的球形，用户全部否掉（"太魔性""比原版差远了""简直是灾难"）。后来才定位到：**保留原版元素，只改形状**。这一点务必先确认，别自己发挥。

---

## 二、踩过的坑（问题 → 根因 → 正确做法）

### 1. 沙漏逻辑（最容易错、被用户首先抓住）
- **错**：把上球做成"上面空"（沙面低、下半是空玻璃），下球反而满。
- **根因**：把"沙子在流动"误当成"快漏完"。实际沙漏**流动时上球是满的**（沙面靠上）、下球才刚开始积。
- **正确**：取"漏了 30%"状态——上球余 70%（沙面靠上）、下球积 30%（小堆）。
- **验证手段**：跑 `python main.py`（桌面预览）+ `Window.screenshot` 抓运行中的真实画面当蓝本，看沙面位置和沙柱形态，别凭直觉。

### 2. 沙柱形状（反复最多）
- **错**：等宽矩形 / 粗圆柱 / 下端锥尖 / 一串等距方块——全被否。
- **对**：**上端喇叭口顺球壁张开（贴住球壁、无缝隙）、中段直筒填满颈管、下端融入下球沙堆**（啮合无缝、无锥尖、无刻意方块）。这就是 `main.py` 里 `_neck_sand_side()`（`in_pts` 贝塞尔）的真实形状：上宽喇叭 → 直筒 → 下开口交给下落沙粒。
- **要点**：沙柱要"细而连贯地流动"，不是粗圆柱，也不是分段的点；下端自然渐变/融入，不要直角或尖锐。

### 3. 体积守恒（用户反复核对）
- 上球沙 + 下球沙 + 沙柱 = **1 球容量**（沙子总量守恒）。
- 本图标取：上 0.63 + 下 0.27 + 沙柱 0.05 = **0.95**，**留 5% 亏空**（用户明确"沙柱也有体积，上下两球之和应小于一球，要留点亏空"）。
- 计算：`v(t)=3t²-2t³` 的球体积反函数（`sand_s`），沙在球内从底部往上的弓形体积分数；按 `上=0.9×0.7`、`下=0.9×0.3` 分配。

### 4. 视觉风格克制
- 玻璃球做**上白下蓝竖直渐变 + 细描边**（原版那种）即可；**不要**顶部月牙高光、底部反光弧、径向浮雕、"灾难"式的立体玻璃感。
- 金沙用纯金沙 `#d9a360` 平的，沙面别额外加一条亮色横线（"沙面上奇怪的横线"被否）。

### 5. 木盖：图标有、App 没有（取舍）
- `main.py` 实际**没有木盖**（纯玻璃双球），但**用户认可用木盖**（原版就有，视觉上像"木框沙漏"）。图标以用户审美为准，**保留木盖**；这是"图标 vs 运行时"可以不一致的地方，以用户拍板为准。
- 木盖位置**必须随画布/球位置自动算**（顶盖贴球顶、底盖贴球底），硬编码坐标在 1080×1920 的 presplash 上会错位跑到两球中间。

### 6. PIL 生成图的几个硬 bug（浪费时间，先记住）
- **`grad_ball` 的透明球粘贴**：`im.paste(g, (..))` 必须传 **mask**（`g.split()[3]`），否则把球 bbox 内圆外的 RGB 也盖上去 → 出现**黑色方框**。
- **`Image.alpha_composite(im, layer)` 返回新图**：之后必须 **`D = ImageDraw.Draw(im)` 重新绑定**，否则后续用 `D` 画的（沙柱、木盖）全画在被丢弃的旧图上 → 图里少了东西。
- **`D.rectangle` 高度为 0**：`[(x-h),y,(x+h),y]` 两个 y 相同画的是没高度的线，完全看不到。方形要用 `y±h`。
- **`/tmp` 路径 Windows 不认**：从 git-bash 写的 `/tmp/x.py`，Windows Python `open('/tmp/x.py')` 会 FileNotFound；把临时脚本放到项目目录用相对路径跑，跑完删。
- **`Window.screenshot(name=…)` 会改文件名**：一定用它的**返回值**去 `Image.open`，别自己拼路径。

## 三、可复用的正确做法

1. **先跑 App 截图当蓝本**：`python main.py` → `Clock.schedule` 里 `on_toggle()` 启动 → 延迟 1.5-2s → `Window.screenshot` 抓运行中沙漏，看沙面位置/沙柱形态/球距，再据此画。别凭空设计。
2. **审美对齐**：先问清用户认可的是"原版质感"还是要全新的；不动"用户已认可"的元素（木盖、配色、居中）。
3. **物理自检**：沙面位置用球体积反函数，保证"上 + 下 + 沙柱 = 1（或按用户要求留亏空）"。
4. **生成脚本放项目内临时文件，跑完删**，别留 `_gen_tmp.py` 之类的进仓库（`git add .` 会带进去）。

## 四、关键参数（icon 1024，`cx=512`，球 `R≈172`）

| 参数 | 值 | 说明 |
|---|---|---|
| 上下球心距 | 上 `(512,315)` 下 `(512,715)`，R=172 | 两球间留 ~40px 间隙给颈管 |
| 颈管玻璃半宽 | `gn=12`（全宽 24） | 细颈，球径约 7% |
| 沙柱 | 上端喇叭 ≈`gn×3`，直筒 `gn`，下端融堆 | 啮合无隙、无锥尖 |
| 上球沙 / 下球沙 / 沙柱 | 0.63 / 0.27 / 0.05 | 合计 0.95，留 5% 亏空 |
| 玻璃渐变 | 上 `#f4fafc` → 下 `#d8e7ef` | 克制，不叠加高光/反光 |
| 木盖 | 棕 `#6f5938` + 两条木纹，贴球顶/球底 | 位置随球自动计算 |

## 五、给下回的提醒

- 图标是"缩小的符号"，允许与运行时简化；但**沙漏的物理直觉、体积守恒、上下球沙分布**这些逻辑性的东西不能错，用户一眼就看出来。
- 宁可先跑 App 截图 + 问清审美，也别急着出图；**需求确认比生成重要**。
- 每次只改一个明确点，改完立即给用户看 + 提交，避免大版本来回。
