沙柱的「断裂」和那条缝 —— 2.93 + 2.94

2026-10-13 · 起因：你的两句判词 ——「下落的沙柱突然会改变形态」「有个突变点 不合理吧」 （更早），以及「快满的时候，沙柱的比较纯色。**隐约还有一个缝隙**」（本轮）。跑了一轮对抗性审查定位。

两句话的结论：
① 「缝隙」= 我 2.86 那次「末段压线宽」的副作用 —— 材质沙柱在出口那一行亚像素漏盖，底下是 亮玻璃底（比沙亮 ~45 级）⇒ 露一点就是一条亮缝。它只值 2px（2.93）。
② 「突变点 / 突然改变形态」的真身是另一个东西：沙流有两条绘制分支，两条曾经不等价 —— 在途粒子跨过 800 颗那一帧，自由落体段整体从「撕裂透光」翻成「实心」（2.94）。
两条都已出货（2.93 / 2.94），下面的数字全部可复跑。

一、2.94（大头）：「突变点」= 两条绘制分支不等价，跨过 800 颗时整体换脸

沙流粒子有两条绘制路径，同一份代码里并存：

  • 逐桶路径：24 个色桶各自更新自己的顶点块；
  • 融合路径（安卓恒走这条）：把全部桶拼成一条长数组、算式只跑一遍（省调用开销）。

选择开关是 FUSE_BUCKETS × 「在途粒子数 ≥ 800」。而两条路径只差一处： 逐桶路径里有 reach（2.82 修的「落沙↔沙堆空横线」—— 把每颗粒的线段下端延伸到接触面）， 融合路径里一个使用者都没有。后果：

量融合（设备实际走的）逐桶（有 reach）
双臂逐像素差（平板口径，t=45.4）—5657 / 5180 / 4992 px（整段自由落体区）
剖面「最长连续沙色」8 ~ 2436 ~ 70
真机逐行（50s 档 t≈46.2→46.7s）20 → 18 → 56 → 56：一秒之内翻过去

2.94 改前（左：融合分支丢 reach ⇒ 整段撕裂透光）vs 改后（右：两条分支一致 ⇒ 实心柱）。 平板口径 1904×2890 / 50s / t=45.4，同刻同倍率。

改法（一处）：融合块里补一行 if reach is not None: np.subtract(bottom, reach[allidx], out=bottom)， 位置与逐桶路径逐字同序（top = bottom + trail 之后、只拉下端 —— 放到前面会被 top_limit 截掉一段）。顺带给 FUSE_BUCKETS 补了设备可达的标记文件 （原来只认环境变量 ⇒ 设备上永远取默认值，想 A/B 也做不了）。

二、2.93：那条「缝隙」= 出口行的亚像素漏盖

四腿闭环（平板口径 1904×2890 / 50s 末段，出口那一行 73px 窗）：

臂露出玻璃底的像素
2.92 出货11 / 73
2.92 + 关掉 2.86 的末段压线宽1 / 73 ← 单变量：压线宽是主因
1.244 参照树0 / 73
2.92 关粒子整段 73/73 = 玻璃色 ⇒ 出口以下没有材质，那一行只由新生粒子盖
中段 t=250 / 73

机制：出口以下没有任何材质沙柱，出口那一行只由刚出生的粒子盖；新生粒子 vy≈35–60， 拖尾触 2px 地板 ⇒ 该行覆盖率只由线宽决定。而 2.86 那次为了治「末段太纯色」把线宽 2px 压到 1px ⇒ 盖不严；底下又是亮玻璃（#eaf3f8，比沙亮 ~45 级）⇒ 一条亮缝。 几何上是一处亚像素漏盖：出口行的像素中心落在沙柱切面下方 0.34px。

2.93 改前（左：材质柱下沿与出口之间露出一行亮玻璃）vs 改后（右：下端补 2px，缝消失）。 平板口径，出口局部 5× 放大。影响面 54 px（恰好 y[1326..1327]）。

改法：OUTLET_OVERLAP（默认 2px）—— 只在材质柱下端就是出口切口时把下端往下补； 下端已经跟着沙面前沿走时不补（那是沙的边界，补了等于画出还没落到的沙）。 一键回退：标记文件 outletoverlap = 0。

三、设备口径：这一态复现不出缝（如实说）

同一状态在设备口径（1080×1920）上，改前（左）改后（右）看不出差别 —— 这一档本来就没露玻璃（中轴 31px 全是沙）。⇒ 2.93 的判据只在平板口径上成立， 设备侧不决定性。2.94 的设备复测也还没做（要装新 APK 跑一次）。

四、这轮对抗审查（跨模型 2 专家 × CP 2 轮 + AP 3 轮）

它推翻了我原来的修法：我提的「补等宽材质柱 / 出生线上移 / 修 pfade」三条里，两条被证伪 （出生线上移的粒子会被 sel = ~(y≥outlet) 整颗滤除，纯延迟零重叠；pfade 是死旋钮且方向反）、 一条降级为备选。它找出真身（融合分支丢 reach）并挖出三个我没想到的活 bug：

ID是什么状态
N1颗粒色调量纲错配（0..1 的亮度拿去和 0..255 的阈值比）⇒ 所有颗粒饱和到最亮档；且那个「×255 修复」代数上等于没做未修（下轮）
N2pfade 的基准值写在 widget 上、读在 batch 对象上 ⇒ 全 texture 路径都不生效；且方向反未修
N3量具 tools/_probe_chunk_need.py 已腐（对当前 update() 签名直接 TypeError）未修

模型披露：指派 deepseek-v4.1-flash[1m] / qwen3.8-flash[1m]； 台本记录为 deepseek-v4-flash / qwen3.8-flash ⇒ 按降级处理： 跨模型合意比同模型强，但不等于验证。完整记录：benchmark_logs/_vid/real22/synthesis_293.md。
