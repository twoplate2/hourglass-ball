验收标准 —— 视觉类改动（含出口以下的下落沙柱）

位置 design/checks/notes/old-acceptance.html · 2026-10-12 首版 · 配套 hourglass.html、QA 纪律（证据等级）、历史判据 A1–A7

起因。 2.78 出货后用户质问「2.78 的 QA 是谁」「这种也能通过？」「我不是让你每次测试都去安卓版本跑吗？」。 复盘：所有闸门都是作者自证的 —— 金标准每改必重标定（只回答"像不像上一版"）、 旋钮关掉一致（只证明"可控"）、剖面单调（只证明"它做了我让它做的事"）； 唯一能判观感的那道闸门（并排图交用户）是我自己看的，而且我预先写了「觉得太多/太少都不用发版」。 装机实测被我降级成"push + 一张缩放模拟器图"，而 pc/apk/CLAUDE.md:51 写的是「桌面三态 + 装机实测」。
这份文件写给"改之前"：不满足就不许说改好了、不许 push。

0. 元规则

  • R0「通过」两个字归用户。 我最多能说两种话： ① 「机械判据 X/Y 通过（附原始输出）」；② 「并排图与设备 1:1 截图在此，待你裁决」。 在用户表态之前写「更自然 / 更好 / 没问题 / 可以发版」都是越权。
  • R1 证据等级（QA_RULES.md 铁律 0）：E1 有对照的实测 · E2 有实测无对照 · E3 只有断言 / 只看了代码 · E4 事后被推翻。没到 E1 不许写"验证通过"；E2/E3 要如实标。
  • R2 作者自证类闸门，各自只能证明一件事（都不能证明"好"）：
闸门能证明不能证明
金标准 _render_golden --check与上一版逐图一致 / 变化范围对不对 —— 它每改必重标定，等于盖章放行
关旋钮逐像素回参照改动可控、可回退开的时候对不对
剖面单调 / 达标它做了我让它做的事那个事该不该做（2.78 剖面 1.1→55.6% 完全达标，结果是错的）
test_physics_equiv / pyflakes没破坏既有契约视觉正确
同帧 md5 稳定不闪图案对不对
  • R3 判据集不许由实现者自选。 至少要有一条与本次改动目标正交的量。 2.78 只量了它自己造的那个剖面 ⇒ 三条正交量（连续性 S1、图案速度 S2、墨量 S3）一条都没进判据集。
  • R4 门槛必须先标定：先拿「已知好」与「已知坏」各跑一遍，门槛要能把两者分开。 本对象的标定对：已知好 = 1.244（用户裁决过的参照）· 已知坏 = 2.78（用户判词：断成虚线）。 分不开的门槛等于没有门槛（旧 A1 的 [0.6,1.5] 已知错也落在里面，属反例）。
  • R5 观感归用户：改像素之前先把改前/改后并排图交上去（项目红线 CLAUDE.md §八）； 统计量只能事后解释"为什么"，不许用来裁决"好不好"。
  • R6 量具的五个已知陷阱（都栽过）： ① 缩放图判细结构 —— 缩图把 1~4px 的缝与亮沙混在一起（我把缝读成亮沙，用户纠正）； ② 行平均覆盖率看不见竖缝、中位数对混合比变化不敏感（要用均值）； ③ 录像不能当量具（编码器对 1~3px 细颗粒有码率呼吸，同一静止区域能摆 2.9 倍）； ④ 窗口污染（下球沙堆是另一个层且静止，窗口压到堆上会得出"材质不动"的假结论）； ⑤ 对照图不同倍率（左 ×10 右 ×3，被读成"放大 2.5 倍"）。

3. 交付物清单（交给用户的那一份）

  1. 并排图：改前 / 改后，同时刻、同口径、同倍率、1:1 不缩放，附标签与 md5；
  2. 设备 1:1 截图（P1），能看清柱子，版本号可见；
  3. 机械判据表：每行 = 判据 / 命令 / 原始输出 / 结论（原样贴，不许转述）；
  4. 回退口：一个真的被读到的旋钮 + 自证输出；
  5. 如实列：已知代价、未验证项、没覆盖的档位。

4. 一票否决（禁用做法）

  1. 用统计量代替眼睛；用「作者觉得更自然」代替用户裁决。
  2. 先 push 再给图（2.78 的顺序）。
  3. 拿「金标准全绿」当「没问题」—— 它每改必重标定。
  4. 拿脚手架通过（旋钮关掉一致 / 单测 / pyflakes）当「视觉正确」。
  5. 没标定过的门槛当依据；缩放图判 1~4px 结构；录像当量具。
  6. 把「机械判据通过」写成「验证通过 / 修好了 / 没问题」而不标证据等级。
