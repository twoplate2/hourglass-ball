# 版本记录怎么写

一轮记录对应 `records/v版本/日期.json`，图文页由资料生成工具构建。
现有 [2.96 的 JSON](../records/v2.96/20261013.json) 是格式样例，不是可复用的结果。

## 必须登记

- 每个版本的规则快照中，**每个编号恰好一条结果**：不能只登记通过项或只写总评。
- 一个编号固定对应一项表现，例如 U00 是整团上沙的整体观感，U02 是上沙动态。
  阶段和边界条件属于这个表现的检查范围。表现实质变化时新增编号，旧编号不能另作他用。
- 新增规则不能替旧版本制造通过结论；旧版补登记的新编号默认未测，并保留原规则与证据。
- 日期、检查人、规则版本、源码版本/摘要、APK 包版本、实际运行环境。
- 周期、配色、浓度、颗粒/起伏档位、实际画布尺寸与 density；无法回读就写未知。
- 用例编号、所处阶段与真实进度，区分真实等待、逻辑推进和跳转取样。
- 原始全图、同位置裁图、原始时间戳和录像；每份资料保留来源及 SHA256。
- 有效自动报告及对应日志，不能只有一句“脚本跑过”。
- 已测、失败、中断、片段观察、未测各自登记；缺项继续保留。
- 改前/改后对照和未修改区域；需要观感判断时保留用户审阅状态。

## 状态不要混用

- **片段观察**：看到了某几个画面，不能代表全过程或整个用例通过。
- **未测**：缺少该用例所需证据，不能删掉该项。
- **失败**：实际结果不满足有效判据，写清复现输入和证据。
- **中断**：执行没有完成，不能当成失败已定位，更不能当作通过。
- **待验收**：实际证据齐备，但尚未完成要求的审阅。
- **通过**：需要当前规则要求的真实执行、正确对象、有效对照和必要审阅。

JSON 状态分别为 `partial`、`not_tested`、`failed`、`interrupted`、
`pending_review`、`passed`。页面单独列“是否测试通过”：通过为“是”，不通过为“否”，
其他状态均为“尚未判定”，不能混成失败或通过。

资料生成器核对：

- `results` 的编号与规则快照完全一致；缺项、额外编号、非法状态或空的实际现象均报错。
- 每份逐项证据必须是项目内存在的文件，且 SHA256 与登记一致。
- 通过项必须有检查人/时间、审阅人/时间、实际现象和证据。
- 通过项还必须有明确运行环境、APK 包版本、源码身份文件及规则快照摘要。

这些核对只能避免漏项、文件错配和无依据的空白通过，不能判断录像中的动作是否正确，
也不能证明运行中用了登记的源码；内容、运行身份和完整覆盖仍由具名检查与审阅负责。
静态资料中的通过登记不代替 CI 或发布门禁。

## 逐项结果格式

下面是结构示例，不是某版本的测试结果：

```json
{
  "results": {
    "U00": {
      "status": "not_tested",
      "actual": "没有整团上沙各进度全貌及完整录像，未执行。",
      "evidence": []
    },
    "U02": {
      "status": "partial",
      "actual": "只观察到开局片段，缺少中段与刷新时刻，尚未完成。",
      "checked_by": "填写实际检查人",
      "checked_at": "填写实际检查时间",
      "evidence": [
        {
          "path": "design/checks/records/v版本/evidence/实际录像.mp4",
          "sha256": "填写该文件的真实摘要",
          "label": "上沙连续录像"
        }
      ]
    }
  }
}
```

实际记录要包括**全部编号**，不能只保留示例中的两个。
目录与文件名用英文或拼音；示例路径不是现有证据文件。
登记 `passed` 时，在该项增加 `reviewed_by`、`reviewed_at`，
在记录顶层增加 `source_identity`（同样为 `path`、`sha256` 对象）
及 `rules_snapshot_sha256`，并填写真实环境和包版本。

## 新建记录时

沿用用例编号，不直接复制旧版图片、观察结果、身份或自动报告。
没有图时保留未测，并说明需要补哪类图；不要生成假的“预期截图”充当实际证据。
正式证据留在版本目录或 `design/images/`，不要只引用以后可能清理的 `_temp/`。

在项目根目录建立某版本的空白记录：

```powershell
python -B src/tools/build_sand_flow_docs.py --new-record 2.97
```

`2.97` 只是命令示例，替换为实际需要登记的版本；本次没有创建或测试 2.97。
命令会生成 `records/v2.97/日期.json`、对应 HTML 与规则快照，
列出所有编号并默认未测，同时更新版本目录页。不会覆盖同版本同日期的已有记录。
同版本另一轮可用 `--date YYYY-MM-DD` 指定日期；同日复测更新该日记录并保留原始证据。

修改 `rules/sand-flow-cases.json` 或新增记录后，在项目根目录运行：

```powershell
python -B src/tools/build_sand_flow_docs.py
```

这只是静态资料生成。应用测试需另获明确任务；PC 自动检查由 CI 执行，
安卓交互使用指定 MuMu，不连接真机。
