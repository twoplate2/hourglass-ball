# 一、`sandmat` —— 沙体材质（6 档）

根因在 `_sand_material_rgba()`，两处：

| # | 代码 | 实测后果 |
|---|---|---|
| ① | 竖直渐变 `0.10*(y-0.5)` | 只有 **±1.3 级亮度**（人眼要 2~3 级）⇒ 宏观上**就是一块平色** |
| ② | 颗粒 = 512² 纹理的**逐像素白噪** | 铺到 ~890px 的球上每颗约 **1.7px** ⇒ 只读成"细噪点"，读不成"沙粒" |

| 标签 | 竖直渐变 | 颗粒粗度 |
|---|---|---|
| `A_current` | 0.10 | 1× ← **当前版本（基线）** |
| `B_grad_mid` | 0.35 | 1× |
| `C_grad_strong` | 0.70 | 1× |
| `D_grain2` / `E_grain3` | 0.10 | 2× / 3× |
| `F_grain2_grad` | 0.35 | 2× |

⚠️ 颗粒档做过 **RMS 归一**（`0.2886751 / sd`）—— **只改"粗细"，不掺杂"强弱"**。
渐变方向 = **上亮下暗**（光照来自上方、越深越暗），物理方向正确。

**产物**：`sandmat_full.png`（整只沙漏，判"离远看"）· `sandmat_upper.png`（1.6× 特写）·
`sandmat_upper_1to1.png`（1:1 不缩放，判"凑近看"）

# 二、`surf` —— 上球沙面微粗糙（4 档）

**代码里有一处不对称，实测量出来的：**

| | 常量 | 设备上实际起伏 |
|---|---|---|
| **下球**沙堆 | `MOUND_ROUGH_FRAC = 0.004` | **3.56 px** |
| **上球**沙面 | `UPPER_ROUGH_FRAC = 0.0014` | **1.25 px** ← **只有下球的 1/3** |

这正好解释两个评审那句"**下面是沙、上面是水**"。
（另注：`UPPER_ROUGH_FRAC` 是**活旋钮** —— 传进 `_surface_roughness` 的 `limit` 就等于它自己的
最大幅度，缩放分支基本不触发，**改多少就是多少**，不像下球当年被限坡钉死的那个。）

| 标签 | FRAC | 设备幅度 |
|---|---|---|
| `A_cur_14` | 0.0014 | 1.25 px ← **当前版本（基线）** |
| `B_r25` | 0.0025 | 2.23 px |
| `C_r40` | 0.0040 | **3.57 px（= 与下球持平）** |
| `D_r60` | 0.0060 | 5.35 px |

**只动这一个变量** —— 漏斗（宽浅坑）没有一起改：
它已经被 `dingbu2.md` 那一轮定过案，而且**平滑的凹面本身就更像液面弯月**，加深它可能适得其反。

**产物**：`surf_full.png` · `surf_upper.png` · `surf_surface_1to1.png`（整条沙面 1:1，**判"直不直"看这张**）

# 顺带：一条工具层面的事实（r15-2号 报的，已核实）

`tools/_review_emu.sh` 的 `seq:<名>:<张数>:<间隔>` **不是标称节奏**：
脚本是 `shot` 完再 `sleep <间隔>`，而每次 `adb screencap` 本身约 0.5 秒
⇒ **标称 0.12 秒的连拍，实际一张约 0.6 秒，慢 5 倍**。
r15-2号 数倒计时量的（10 张走了 6 秒）。
⇒ 历次简报里"连拍 8 张 0.12 秒"实际覆盖的是 **~5 秒**，不是 1 秒。
以后要更密的连续帧，得用 `screenrecord`，不能用 `seq`。
